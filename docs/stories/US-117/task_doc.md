# US-117: Record structured match results from booking win controls
**Status:** Ready for UAT · **Category:** development · **Points:** 3 · **Sprint:** —

## Summary
Each result the player enters with a "Winner" button is now stored as a match record (who fought, who won, which week). The simulation can use real outcomes and never guesses a winner. The player can undo the most recent result, which reverts that win.

## What was built
- `universe/matchResults.js`: pure helpers `createMatchResult` and `applyWin`. Also the undo logic used by the reducer.
- `universe/UniverseContext.jsx`: reducer cases `recordResult` (action `{type:'recordResult', result}`) and `undoLastResult`. Results are stored in `universe.matchResults` and persisted by the Universe autosave under `wwe-universe-v2`.
- `App.jsx`: wires `matchResults`, `onRecord` and `onUndo` into `MatchGenerator`.
- `components/MatchGenerator.jsx`: per-participant "Winner" buttons, "Result recorded: {name}" panel, "Undo last result" button with summary.
- `index.css`: `.winner-button`, `.result-recorded`, `.undo-result`.
- `.gitignore`: `/dist` ignored (generated by `npm run build`).
- Tests: `universe/matchResults.test.js`, `components/MatchGenerator.test.jsx`, `App.test.jsx`.

## How it works
- **AC 1 (Result stored):** Clicking "Winner" next to a participant stores one MatchResult with `week`, `type`, `participantIds` (all participants) and `winnerIds` (the selected wrestler). That wrestler's `wins` increases by 1. No other field changes. The Winner buttons then disable, so the same match cannot be recorded twice. Rerolling or changing the week clears the panel.
- **AC 2 (No assumption):** Generating or rerolling without clicking "Winner" leaves `matchResults` and `wins` unchanged.
- **AC 3 (Existing controls unchanged):** Roster +/− buttons still change only `wins` (minimum 0) and create no MatchResult. Status and champion controls are unchanged.
- **AC 4 (Undo last):** "Undo last result" appears only when at least one result exists and names it ("Week {n} {type}: {winner} won"). Each click removes the most recent result and reduces each winner's `wins` by 1, never below 0. The button disappears when no results remain.
- **AC 5 (Persisted):** `matchResults` is restored after a page reload from `wwe-universe-v2`. Invalid or missing data yields an empty list without crashing.
- **AC 6 (Referenced wrestler deleted):** Undo removes the MatchResult even if a winner no longer exists in the roster, and does not throw.

## How to test
Automated: `npm run lint --silent`, `npm run test:run --silent`, `npm run build --silent`.
Focused: `npx vitest run universe/matchResults components/MatchGenerator App`.

- **AC 1:** Run `npm run dev`, Generate Match, click Winner. Verify: "Result recorded: {name}", winner's wins +1, buttons disabled. Reroll or change week clears the panel.
- **AC 2:** Generate or Reroll without Winner. Verify: no wins change, no Undo button.
- **AC 3:** Use roster +/−. Verify: only wins change; no Undo button appears.
- **AC 4:** Verify: "Undo last result" shows "Week {n} {type}: {winner} won"; click until it disappears; wins drop each time, never below 0.
- **AC 5:** Record a result and reload. Verify: Undo button still shows; `matchResults` is stored in `wwe-universe-v2`.
- **AC 6:** Remove a winner on the Wrestlers page, then Undo. Verify: result removed, no error.

## Known limitations
- Events linked to an undone result are not deleted. They stay and are flagged `sourceUndone` (assumption, to be built with US-128).
- Auto-picking winners and editing historical results beyond undo-last are out of scope.
- `dist/` is still tracked in git until the manual `git rm --cached` step is done. Release is blocked until then.
- AC 6 has no dedicated reducer-level test for a removed winner. The logic was verified by code reading only.
